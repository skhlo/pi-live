# OpenAI tiktoken table rights - #515

Captured 2026-09-24 UTC. Narrow question: do official OpenAI sources establish terms for redistributing the **exact** `cl100k_base.tiktoken` and `o200k_base.tiktoken` bytes inside a third-party native addon?

## Finding

**Qualified yes.** An official repository maintainer stated that the repository's MIT license applies to the encoding files. That directly answers the question for the then-named `cl100k_base` file. Official source later identifies the exact `o200k_base` blob as another encoding file by URL and SHA-256, so the same category statement supplies a reasonable MIT redistribution basis for it too. Applying a 2023 category statement to a file added in 2024 is inference, however, and the statement is an editable GitHub comment rather than immutable committed terms. A stricter gate requiring an immutable, exact-file-specific grant is therefore not satisfied.

**`cl100k_base`: direct but mutable license-scope evidence.** [Issue #92](https://github.com/openai/tiktoken/issues/92) expressly asks about `cl100k_base` and its external blob URL. On 2023-04-05, `openai/tiktoken` collaborator `hauntsaninja` [answered](https://github.com/openai/tiktoken/issues/92#issuecomment-1497875652): “The license in this repo applies to the encoding files as well. Thanks!” The [commit-pinned LICENSE](https://github.com/openai/tiktoken/blob/bfe00ad1bf59fac47513b45fe5173672dcbbcbb4/LICENSE) is MIT and permits distribution of covered copies with its copyright and permission notice. Thus the comment directly connects that license to the already named `cl100k_base` encoding file; if relied on as OpenAI's license-scope statement, MIT supplies redistribution terms without a format-specific native-addon restriction. The GitHub comment is **editable, not immutable**. Its unauthenticated API record had `author_association: COLLABORATOR`, `created_at` and `updated_at` both `2023-04-05T17:39:39Z`; captured body SHA-256 `e530ceba62428da22333e164e72d7c6a1b44492966c065db1fbc34b619780d90`. Those observations do not turn the comment into a committed license.

**`o200k_base`: applicability remains an inference.** The same maintainer added its URL and exact hash in [commit `9d01e5670ff50eb74cdb96406c7f3d9add0ae2f8`](https://github.com/openai/tiktoken/blob/9d01e5670ff50eb74cdb96406c7f3d9add0ae2f8/tiktoken_ext/openai_public.py) on 2024-05-13, after the 2023 comment. The [0.7.0 LICENSE](https://github.com/openai/tiktoken/blob/bfe00ad1bf59fac47513b45fe5173672dcbbcbb4/LICENSE) remained MIT, and its [changelog](https://github.com/openai/tiktoken/blob/bfe00ad1bf59fac47513b45fe5173672dcbbcbb4/CHANGELOG.md) announced GPT-4o support. Treating “encoding files” in the earlier comment as covering this later blob is plausible, especially given the same maintainer's commit, but it is **legal/source-scope inference**, not a later immutable statement granting redistribution of these exact data bytes. No inspected committed notice expressly addresses embedding either table in a third-party addon.

The repository MIT text licenses “software and associated documentation files”; these separately hosted tables are not members of the source tree or official Python packages examined below. The collaborator comment supplies the direct scope bridge for `cl100k_base`; the software license or PyPI `MIT License` metadata alone does not prove that the external bytes are covered. Public HTTP access and a source loader that downloads the tables establish availability for use, not redistribution permission.

The MIT text permits distribution and requires its copyright and permission notice in copies or substantial portions; it does not impose a native-addon-specific condition. Whether the mutable, pre-`o200k` maintainer statement is durable enough for G0 is an evidence-policy decision, not a further source fact. This is an evidence limit, not a conclusion that redistribution is forbidden or infringing.
